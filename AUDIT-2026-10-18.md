## Архитектура и безопасность

`index.html` подключает закреплённую версию `@supabase/supabase-js@2.45.4`; сначала загружаются конфигурация/auth, затем данные курса, последним — `app.js`. Публичный клиентский ключ в `js/config.js` проверен на тип publishable/anon; service-role/secret ключей в конфигурации не обнаружено. `supabase/schema.sql` содержит включение RLS, owner-scoped `auth.uid()` политики, атомарный RPC сохранения и удаление аккаунта с каскадом прогресса. Это статическая ревизия, а не динамический тест прав в реальной базе.

В `app.js` остаются `innerHTML` вставки для шаблонной разметки. Просмотрены текущие вставки: навигация и иконки формируются из констант, имя/email пользователя и ошибки ответов экранируются, заметки и сообщения обратной связи читаются через `textContent`. Импортные заметки проходят через экранирование перед показом, а тест санитизации проверяет XSS-подобный текст. Полный автоматизированный data-flow аудит всех шаблонов всё ещё не проведён; перед внешним запуском это остаётся P1 security review. Удержание Tab проверено, но возврат фокуса после закрытия не подтверждён.

## Запуск

Из корня проекта:

```sh
python -m http.server 8000
node scripts/validate-project.js
node scripts/validate-data.js
```

Откройте `http://localhost:8000/`. GitHub Pages и OAuth redirect URLs сверяйте с актуальными настройками владельца; никаких изменений в production-сервисах эта ветка не делает.
